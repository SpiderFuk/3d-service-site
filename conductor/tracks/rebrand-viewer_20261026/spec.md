## Summary

Rebuild section 08 Visor 3D (`#visor`) from `design/landing-v1/BUILD.md`: a lazy-loaded Three.js viewer in a white frame with tomate extrusion, four example models, explicit empty/loading/loaded/error states, mouse/touch/keyboard rotation, and WhatsApp hand-off messages per file.

## Context

The current `ModelViewer` + `viewer/*` components show dimensions, volume and triangle counts, use OrbitControls with zoom, and load eagerly. The new viewer shows no measurements, only rotates the model, stays in the browser, and loads Three.js only when the visitor gets near the section. The loader factory (`src/lib/loaders/`) and rotation fix in `ThreeCanvas` are reused.

## User Story

As a visitor with an STL or 3MF, I want to open it in the page and turn it around before sending it, so that I can check it is the right piece and ask for a price with one tap.

## Technical Notes

- Lazy load: IntersectionObserver with a generous `rootMargin` (e.g. 600px) → `await import('$lib/three/viewerRuntime')` that pulls in Three, loaders and scene setup. Check `npm run build` output to confirm a separate chunk.
- Rotation: replace OrbitControls in this viewer with a small yaw-rotation controller (pointer events, horizontal delta → `rotation.y`; arrows ±15°), no zoom/pan. Keep the existing orientation correction and camera-distance fit.
- Progress: read with `FileReader` `onprogress` (or a streamed `Response` for examples) to drive the percentage.
- Errors: extension check → type error; `size > 50 MB` → size error (no parse attempted); loader throw → corrupt error.
- Material: single cobalto `MeshStandardMaterial` (read the token value from CSS at runtime so the color stays in one place).
- Example mapping: Santa borracho → `DrunkSanta.stl`, Miniatura → `mini.stl`, Jarrón → `FlowerVase.stl`, Cuadro en relieve → placeholder until the owner's file arrives. `DiceTower.stl` is no longer shown.
- Dispose the scene, geometries and renderer on destroy and on "Probar otro" (CLAUDE.md rule).
